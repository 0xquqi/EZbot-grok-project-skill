# 发现、关联与增量更新

## 找到具体项目

以Bot内置公开X主动搜索为主，按grok-runtime.md选择当前工具。工具支持时，新近发现优先Latest；Top只辅助找背景，不能独占首轮。生态名、参与动作、当前候选项目名/账号/合约可结合查询，中文和英文都考虑；../assets/defaults.json 的种子只是起点，不要求原帖同时含精确词组，不穷举所有组合。顺着引用、父帖和官方链接解决简称与省略上下文。指定账号是补充来源，不是唯一入口。

把探索与核实分开，不要一次查询叠满所有门槛：

1. 用少量生态名+参与动作找新近线索；语义搜索可补“使用币安Agent ID作为资格的新活动”这类描述。模式不可用就以不同表述的关键词检索替代。
2. 发现候选后，用项目名、独特活动词、完整CA或已确认账号定向补查，读取原帖、父帖/引用与相关回复。社区评论只是线索，不能直接当官方规则。
3. 某组词无结果先检验别名、语言或省略生态名的上下文，不先断言无新项目；已找到具体对象就进入研究，避免一直搜不交付。

区分“项目本身是什么”与“它为什么属于本生态”：生态关系可来自明确原帖、官网规则或身份依赖。普通BSC代币、AI Agent字样或.ai域名本身不足以证明关联。对象具体但生态关系未确认时可作为待核实线索展示，不能混入已确认名单或宣称其满足生态资格。

优先直接公告与可追溯来源。转发、教程、汇总只能提供候选线索，沿引用追原始来源；找不到原始来源就说明仅有二手信息。平台名、排行榜名或多项目汇总不是独立项目。低热度、缺网站或尚无合约不自动淘汰；能指认具体对象的早期线索可以说明已知内容与缺口，不凭空补玩法。

结果重复或过宽时调整查询；有截断且仍需补查时分页/缩小时间片。按本轮可用时间和用户数量限制处理，优先交付具体新项目与实质更正。已掌握信息足以回答基本问题、进一步检索不再补充关键证据或宿主预算耗尽时收束；不要无限换词追求全量。一次失败可重试一次或改用一个合理公开来源，持续不可读就留缺口。

## 入选与重要变化

时间窗筛选的是线索，不是要求项目必须在窗口内诞生。项目已存在但本轮出现新的具体活动、明确开放预告或实质变化，仍应研究；只有历史讨论/转发、没有新活动或变化时不包装为本轮新项目。索引延迟或补查才取得的窗口外线索，可标“补充线索”并注明原始时间，不混进窗口内统计。

“发现类型”和“活动阶段”分开判断：首次发现/重要更新/待核实是记录分类，预告/开放/暂停/结束/未知是阶段。具体且相关的预告也可以编号为新发现或待核实线索，写明尚未开放及缺少什么；不因为没合约、未开mint就丢入其他动态。已确认项目出现未证实的重要变化，标题可标重要更新并明确“项目方宣布，链上未核实”。

重要变化包括新活动或入口开放、目标合约迁移、资格/费用/产物/退出规则变化、实现或关键权限改变、关键风险出现/解除、此前关键缺口取得实证。普通供应增长、重复宣传和热度变化通常不单独通知；达到售罄/跨阶段阈值则重新判断。换合约先保留同一项目的旧/新资产与迁移关系，核官源、链、用途和旧资产处置，不直接覆盖旧地址或把新CA当全新项目。

汇总前对照编号卡与其他动态：存在上述重要变化就不能概括为“已知项目没有重要变化”。未查完、限量未展示和确无结果分别表述。排版复验可重排历史材料并保留原时点，不重置去重、不记成新发现或新搜索。

## 区分来源、项目与活动

- 来源：保留原帖ID/链接、作者、发布时间、实际观察时间、取得内容及完整程度。搜索摘要不能反写成完整原文。
- 对象：区分平台、项目家族、资产与活动。记录链、目标地址及角色，缺失时用稳定内部ID关联已确认账号/专属域名与活动描述。
- 同链同目标合约且角色/活动相符，或官方明确指向同一对象时可合并；同名、同推广者、同支付币、共享注册表/工厂不够。同项目新资产或新活动保留独立记录。
- 保留最早实际观察时间，分别记录原帖发布时间、代码核对时间和动态状态读取时间。历史帖不能包装成窗口内新发行。

同帖多次命中合并来源；同项目不同帖子补充证据。先关联再研究，避免每轮重做。代码/机制未变可复用原结论并保留原检查日期；当前费用、供应、阶段与暂停状态需要刷新或明确时点。实现升级、规则/费用变化、官源冲突或新风险触发对应部分重查。

## 持久状态

在grok-runtime.md约定的`/workspace`工作流目录保存记录，读取现有配置和state后再运行；任务目录与routine绑定同一个workflow-id。用云终端或实际文件工具读写，状态保存后确认可读。保存state.json：schema_version、配置、检查范围/缺口、来源、项目及活动身份、证据/结论与日期、待补问题、上次通知内容、运行状态、首次试运行完成标志、本轮编号映射及结束通知状态。不要包含凭证、私聊或个人钱包状态，不把内部路径放进对外回复。

仅把实际取得并保存的范围推进为已检查；未覆盖或失败范围保留。后续搜索从上轮检查范围继续，允许小幅重叠以处理索引延迟；记录中断缺口，不能把定时触发时间当作已经完整查过。去重不是全量覆盖证明。

宿主支持时原子写入并取得实际运行锁；同工作流串行处理，不声称提示词自带锁。重叠触发可合并待查范围。没有可协调的锁/串行机制时不声称已防止并发，并说明调度限制。无持久存储时利用当前对话上下文去重，同时说明跨运行状态不能保证；状态丢失则标基线缺失，不把所有旧项目重新说成新发现。

通知只比较实质内容，时间戳、点赞量或重复宣传不触发重复报告。已结束对象一般不反复研究，新活动/重新开放再更新。资料不足对象保留待补问题，避免同一失败对象占满下一轮。
