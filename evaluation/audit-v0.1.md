# v0.1 发布前审计

审计日期：2026-10-28。范围：全部11份 Skill 源文件、使用/更新说明、构建脚本、来源记录、人工情境检查及仓库交付边界。保持版本 v0.1，以内容哈希区分修订。

## 发现与修正

| 问题 | 修正及对应位置 |
| --- | --- |
| 发现类型与活动阶段容易混用，预告可能被漏掉 | discovery-state：具体预告可以编号；阶段与新发现/更新分类分开。 |
| 换合约被埋在其他动态，汇总仍声称没有重要变化 | discovery-state/output：明确重要变化条件，保留新旧资产关系，汇总须与卡片一致。 |
| 多处官方宣传可能被误算作独立验证，冲突缺处理顺序 | research-flow：逐主张记录来源、类型、适用条件和时点；核链/阶段/单位后保留未解冲突。 |
| 经济研究容易停在奖池数字，忽略实际用途和退出 | research-flow：检查需求、奖励来源、分母、解锁和控制权；缺价格/退出不算收益。 |
| 代理源码、实现代码、入口状态容易错配；owner判断过强 | fees-contracts：核代理/实现/区块，分别检查角色、升级和实际控制者。 |
| 余额上限、局部流动性、单站缺源码、历史Gas容易过度推断 | 保留原有范围限制；补历史Gas和交易失败阶段的限定。 |
| 同版本附件被口头称为云端已更新，难判断具体修订 | startup：区分采用、持久保存、运行；提示词和清单新增源内容标识。 |
| 重复测试易误清去重或把历史材料当新发现 | startup/discovery：允许单独排版复验，保留时点和真实去重状态。 |
| 构建检查依赖assert，可被Python优化模式跳过 | build_release拒绝-O；新增隔离测试验证拒绝路径。 |
| 发布包未附上游许可，历史包混在本地目录 | 加入同作者上游MIT声明并打入ZIP；仓库忽略旧包、状态、截图和凭证，明确文件清单。 |

## 验证方法与边界

- 构建检查实际解析 YAML、配置及模板，检查相对引用、全文嵌入、逐文件哈希、ZIP CRC和内容一致性。
- `tests/test_release.py` 在临时副本验证：同环境重建一致且不收运行文件、源码改动使交付过期、ZIP多出文件被拒、失效引用被拒、本机路径被拒，以及优化模式不能跳过校验。
- `review.json` 是27类人工规则审阅，不是自动模型测试。`behavior-cases.md` 提供10组虚构材料供真实Bot复验，尚无线上通过记录。
- 重新查阅Grok官方能力、调度和X搜索文档；Bot能力与API工具参数仍分别描述。不会把官方能力说明当成用户账号的执行记录。
- 尚未在Grok Bot复跑此次修订；未独立核验用户此前输出里的项目事实，也未声称完成项目合约全面安全审计。

当前可发布为需继续试运行的工作流。最值得下一步验证的是：预告/换CA分类、动态页补查、跨轮状态、结束消息实际投递，以及复杂项目的证据约束是否被模型遵循。
